# 审阅框架按分析的层次展开：问题与结论 → 数据来源与处理 → 分析方法与比较 → 关键数据的准确性 → 结果的呈现 → 解读与不确定性 → 可复现性。概览写分析的架构，正文批注只处理细节。
aspects:
  - id: question
    name: 问题与结论
    ask: 分析回答了什么问题，结论是什么？
    criteria:
      - 开头即给出问题与结论，读者读完第一段就知道答案及其可靠程度
      - 结论回答的正是被提出的问题，而不是一个更容易回答的相近问题
      - 写明结论可以支持什么决策，不能支持什么决策
    expert_questions:
      - 被提出的问题原文是什么？文档回答的是这个问题，还是一个相近而更容易回答的问题？
      - 读完第一段，读者是否知道答案以及它有多确定？
      - 结论能直接用于什么决策？文档是否说明了这一点？
      - 结论中的比较对象与基准是什么？读者是否需要读到后文才知道？
    red_flags:
      - 结论放在文末
      - 回答了一个没有人提出的问题
      - 只给出数字，没有给出结论
  - id: data
    name: 数据来源与处理
    ask: 数据能否代表结论所指的对象，处理过程是否合理？
    criteria:
      - 数据来源、时间范围、覆盖人群与样本量写清楚
      - 筛选、合并与去重的步骤写清楚，每一步删除的数据量及原因有说明
      - 缺失值与异常值的处理方式写明
    expert_questions:
      - 数据覆盖哪段时间、哪些人群？与结论所指的对象是否一致？
      - 每一步筛选删除了多少数据？被删除的部分是否恰好在关键特征上与保留部分不同？
      - 缺失值如何处理？是否被当作 0，或被悄然删除？
      - 合并数据表时是否可能产生重复行或丢失行？合并前后的行数是否核对过？
      - 数据的定义（例如“活跃用户”“转化”）在不同时期或来源之间是否一致？
    red_flags:
      - 样本量前后不一致且未解释
      - 筛选条件改变了样本的构成而未说明
      - 使用了过期的数据版本或口径已变更的指标
  - id: method
    name: 分析方法与比较
    ask: 分析方法是否适合这个问题与这份数据，比较是否公平？
    criteria:
      - 比较的各组口径一致，除所关心的因素外没有系统性差异
      - 统计方法的前提大致成立，报告了不确定性
      - 主要结论由最直接的比较即可看出，对合理的分析设定稳健
      - 与结论不符的数据得到正面处理
    expert_questions:
      - 被比较的两组在其他方面是否也不同（季节、人群构成、渠道、版本）？差异是否可能来自这些因素？
      - 同一个人或同一个账户是否被重复计入？计算不确定性时是否考虑了这一点？
      - 前后对比是否有对照组？如何区分处理效果与原有趋势？
      - 共尝试了多少种分组或切分方式才得到这个结果？
      - 最直接的比较（两组均值、交叉表）是什么样？复杂方法得出的结论在直接比较中是否也能看出？
      - 有哪些数据与结论不符？每一处如何解释，是否动摇结论？
      - 如果结论成立，其他数据中还应当观察到什么？是否检查过？
      - 分析者是否阅读过若干条原始记录，确认数据所记录的正是所设想的事件？
    red_flags:
      - 前后对比没有对照组，把趋势当作效果
      - 均值掩盖了分布，少数极端值主导结果
      - 进行了大量分组比较，只报告显著的一组
      - 结论只依赖一个模型或一种设定
  - id: correctness
    name: 关键数据的准确性
    ask: 结论所依赖的数据是否与分析输出一致？
    criteria:
      - 结论所依赖的关键数据与已保存的输出一致
      - 换算正确（百分比与百分点、比率、增长率的基数）
      - 分组数据与总数相互吻合
    expert_questions:
      - 结论所依赖的三到五个数据，能否在输出中找到出处？
      - 是否混用百分比与百分点？“增长 50%”的基数是多少？
      - 各分组数据相加是否等于总数？
      - 文中的数据与图表中的数据是否一致？
    red_flags:
      - 百分比与百分点混用
      - 基数很小却报告很大的百分比变化
      - 正文数据与图表或输出不一致
  - id: presentation
    name: 结果的呈现
    ask: 图表与文字能否让读者迅速抓住结论？
    criteria:
      - 每张图表达一个结论，标题即结论
      - 坐标轴、单位与误差范围说明清楚，不造成误导
      - 每个结果先给结论，再给证据
    expert_questions:
      - 只读图的标题，能否得到结论？
      - 坐标轴从哪里开始？差异是否被截断的坐标轴放大？
      - 误差线表示什么（标准差、标准误、置信区间）？是否说明？
      - 一段文字中是否罗列了过多数据，使读者抓不住重点？
    red_flags:
      - 图的标题只是变量名
      - 截断坐标轴夸大差异
      - 关键结论没有对应的图表，或图表与结论不一致
  - id: reading
    name: 解读与不确定性
    ask: 结论是否与证据相称，读者会如何理解并据此行动？
    criteria:
      - 相关不写成因果，统计显著不写成“重要”，不显著不写成“没有差异”
      - 不确定性与局限写在读者使用结论的地方
      - 读者照字面理解不会产生误读（比较对象、基准、效应大小）
    expert_questions:
      - 读者照字面理解会采取什么行动？分析是否支持这样的行动？
      - 哪些句子用了“导致”“带来”“提升了”这类因果表述，而分析并无因果设计？
      - 效应的实际大小是多少？它在业务或实践上是否有意义？
      - 局限写在哪里？读者使用结论时能否看到？
      - 结论能推广到什么范围（其他时期、其他人群、其他产品）？
    red_flags:
      - 使用因果表述，但没有因果识别
      - 不确定性只出现在附录或脚注
      - 将小样本或短时期的结果推广到全体
  - id: reproducibility
    name: 可复现性
    ask: 他人能否根据文档复现与更新这些数据？
    criteria:
      - 数据版本、查询或代码位置、运行方式写清楚
      - 关键数据由代码生成，而不是手工抄录
    expert_questions:
      - 半年后他人要更新这项分析，应从哪里开始？文档是否说明？
      - 是否有手工步骤（在表格中修改数据、手工抄录数字）？
      - 查询中的筛选条件与日期范围是否写在文档中？
    red_flags:
      - 未写数据版本或代码位置
      - 关键数据手工抄录

# 数据分析写作

审阅按分析的层次展开：问题与结论、数据来源与处理、分析方法与比较、关键数据的准确性、结果的呈现、解读与不确定性、可复现性。上游的问题会传导到下游，因此判断从上游开始。分析写作（分析备忘、周报中的分析、给合作者的数据说明）通常篇幅短，读者时间紧，结论会被直接用于决策。最严重的问题是口径或比较方式有误而读者照用；其次是结论不在开头、图表难以读懂。

**审阅分两层。** 概览写分析的架构：结论、数据、方法、可靠程度，以及决定结论能否使用的几个关键问题。正文批注只处理具体段落的细节。架构层面的问题写进概览，不散落在正文中。

**证据链检验**来自 Freedman（1991）"Statistical Models and Shoe Leather"：令人信服的结论来自清晰的比较与对竞争性解释的逐一排除，而不是来自统计模型。它贯穿分析的各个方面，单独列出以免被忽略。

**审阅者的角色**：一位资深的数据分析师，在分析发出之前审阅。阅读文档，必要时阅读查询、代码与已保存的输出，以理解分析过程；不运行代码，不重新计算结果。

**通用要求**
- 写法按 `skills/WRITING.md`：先写事实，再写判断；用学术写作的正常语言。判断时说明：读者照这个结论行动会产生什么后果。
- 能修改的由 AI 直接修改（数据与输出不符、换算错误、结论与数据不一致、因果表述强于证据）。需要作者判断或补充材料的写成建议；需要对照数据、代码或输出核实的写成待核实；关于证据或论证的疑问写成值得追问。
- 表述层面的问题每次最多五条，只列出不修改。结论不清、读者可能误读的问题不属于表述问题，按其影响处理。
- 只核对结论所依赖的关键数据，指出输出文件中的具体位置。

**轻量审阅**只看问题与结论、比较的口径、关键数据与结论是否相称。

## framing · 问题与结论的对应 · J · 问题与结论
- **常见问题**：结论回答的是另一个问题；结论放在文末；问题本身没有写明；只罗列数字而不给结论。
- **依据的材料**：文档本身；提出问题的来源（邮件、任务说明）。
- **审阅要点**：写出被提出的问题与文档给出的答案，比较两者；检查第一段是否给出结论及其可靠程度。
- **作者的参与**：被提出的问题以作者所述为准。

## data_source · 数据来源与覆盖范围 · J · 数据来源与处理
- **常见问题**：数据的时间范围或覆盖人群与结论所指的对象不一致；使用了过期的数据版本；指标定义在不同时期或来源之间发生变化。
- **依据的材料**：文档；读取数据的查询或代码（只阅读）。
- **审阅要点**：写出数据实际覆盖的对象与结论所指的对象，判断两者的差距是否影响结论。
- **作者的参与**：数据来源说明不清时参与。

## processing · 样本筛选与数据处理 · J+V · 数据来源与处理
- **常见问题**：筛选条件删除了与保留部分系统性不同的样本；合并时产生重复行或丢失行；缺失值被当作 0；样本量前后不一致。
- **依据的材料**：文档；处理数据的代码（只阅读）。
- **审阅要点**：逐步阅读筛选与合并过程，判断每一步删除的是哪些样本、是否可能改变结论；核对文档所述的步骤与代码是否一致。影响大小需要重新计算的，写成待核实。
- **作者的参与**：发现不一致时参与。

## method · 比较的口径与对照 · J · 分析方法与比较
- **常见问题**：比较的两组口径不一致；前后对比没有对照组，把趋势当作效果；同一单位被重复计入而不确定性未作相应处理。
- **依据的材料**：文档；分析代码（只阅读）。
- **审阅要点**：写明"比较的是谁与谁、相差在哪里"；列出两组之间除所关心因素外的其他差异，判断它们能否解释结果。
- **作者的参与**：比较方式存在几种合理做法时，提供可选方案；关键时写入概览的关键问题。

## robustness · 分析设定与稳健性 · J · 分析方法与比较
- **常见问题**：时间窗口、分组方式、异常值处理或模型设定存在多种合理做法，文档只给出一种且未说明理由；进行了大量切分，只报告显著的部分。
- **依据的材料**：文档；分析代码（只阅读）。
- **审阅要点**：列出可此可彼的设定，推断换一种做法时结论可能如何变化；判断报告的结果是否经过挑选。
- **作者的参与**：多种合理做法可能导致不同结论时，提供可选方案。

## detective · 证据链检验 · J+V · 分析方法与比较
- **常见问题**：主要结论只依赖一个模型；与结论不符的数据被略过；结论的其他推论未经检验；无人阅读原始记录。
- **依据的材料**：文档；输出文件（寻找与结论不符的数据）；少量原始记录（读几条，不读全部）。
- **审阅要点**：列出主要结论的推论，判断是否经过检验；在输出中寻找与结论不符之处，判断最可能的解释；写出最有力的竞争性解释及能够区分两者的证据；判断最直接的比较能否看出结论。
- **作者的参与**：这里的发现大多写成值得追问；确有错误的写成建议或由 AI 修改。

## numbers · 关键数据与换算 · V · 关键数据的准确性
- **常见问题**：结论所依赖的数据与输出不一致；百分比与百分点混用；增长率的基数有误；分组数据与总数不吻合。
- **依据的材料**：已保存的输出。
- **审阅要点**：只核对结论所依赖的几个数据，在输出中找到出处，检查换算。不一致时由 AI 直接修改。
- **作者的参与**：可抽查核对过的数据。

## figures · 图表 · J · 结果的呈现
- **常见问题**：图与结论不对应；坐标轴截断夸大差异；误差范围的含义未说明；图的标题只是变量名。
- **依据的材料**：文档中的图与图注；作图代码（图形本身无法读取时列入"本次未核查"）。
- **审阅要点**：对每张图，判断读者一眼能看出什么，是否就是作者想说明的结论。
- **作者的参与**：图形本身需要作者查看。

## clarity · 结论的呈现 · J · 结果的呈现
- **常见问题**：结论不在开头；一段文字罗列过多数据；结果小节未先给出结论；关键结果缺少效应大小与不确定性。
- **依据的材料**：文档本身。
- **审阅要点**：只读第一段与各图标题，判断能否得到结论；用一句话写出读者最应记住的结论，检查文档是否突出它。
- **作者的参与**：核心信息以作者意图为准。

## reader_reading · 读者可能的理解 · J · 解读与不确定性
- **常见问题**：数据本身无误，但读者会误读（比较基准未说明、相对变化与绝对变化混淆）；不确定性写在附录，读者使用结论时看不到。
- **依据的材料**：文档；方法部分。
- **审阅要点**：对关键结论，写出读者照字面的理解及可能采取的行动，与分析能够支持的结论比较。
- **作者的参与**：目标读者由作者决定。

## conclusion · 结论与证据是否相称 · J · 解读与不确定性
- **常见问题**：相关写成因果；统计显著写成"重要"，不显著写成"没有差异"；小样本或短时期的结果推广到全体；结论中出现分析未涉及的论断。
- **依据的材料**：文档的结论部分与前述各项的判断。
- **审阅要点**：将结论中的每一句话对应到具体结果；无法对应或强于结果的，由 AI 修改或写成建议；判断结论的推广范围是否与数据覆盖的范围相称。
- **作者的参与**：推广范围由作者判断；关键时写入概览的关键问题。

## handover · 可复现性与交接 · J+V · 可复现性
- **常见问题**：未写数据版本、查询或代码位置与运行方式；关键数据手工抄录；筛选条件与日期范围只存在于代码中。
- **依据的材料**：文档；项目目录（只查看文件是否存在，不运行）。
- **审阅要点**：判断他人半年后接手时能否从文档找到起点；核对文档提到的代码与数据文件是否存在。
- **作者的参与**：一般不需要作者参与。
