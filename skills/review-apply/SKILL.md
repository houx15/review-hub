# review-apply：按反馈修改，最后写回

## 怎么调用 RH
`RH` = `uv run <engine_root>/scripts/rh.py [--workspace <工作区>] <命令> ...`（`engine_root`：本 skill 目录 `realpath` 往上两级；`--workspace` 写在命令名之前）。

## 输入
- 会话文件夹里的 `feedback.jsonl`、`findings.jsonl`、`changes.jsonl`、`threads.jsonl`、`map.json`、`sources.json`。
- `artifact/`：产出的副本，AI 自审时已经改过；`baseline/`：会话开始时的原版。

## 输出
- `work/apply-<轮次>/todo.json`、`todo.md`：这次要改什么（`RH apply-plan` 生成）。
- 改过的 `artifact/`，每一处改动都记在 `changes.jsonl`。
- `findings.jsonl` 里不改的发现追加 `status: closed`；`map.json` 里决策点状态更新（改选的 `changed`，其下游 `invalidated`，确认过的 `confirmed`）。
- 用户同意后写回原文件。

## 步骤
1. **整理清单**：`RH apply-plan <会话>`。
   - 用户没有回应的重大问题不动，在给用户的说明里提一句。
   - 清单分几类：撤销 AI 自改、还没回复的讨论、要改（"一类问题"连同同类实例）、改选的决策点、用户的回答、用户标为有问题的主张、下游失效、用户自己改、不改关闭、没有回应的 S3。
   - 有没回复的讨论：先按 `review-open` 第 5 步回复，讨论的结论可能改变要改什么。
2. **把清单用几行中文告诉用户**，然后 `RH apply-plan <会话> --write`：脚本关闭不改的发现、更新决策点状态。
3. **撤销**：对每个要撤销的改动，在 `artifact/` 里把 `after` 换回 `before`，然后 `RH set-change-status <会话> R001 reverted`（脚本会检查改后的文字确实不在了）。撤销的改动依赖别的改动时，一并说明。
4. **继续改副本**：`RH revise-begin <会话>`，然后直接改 `artifact/` 下的文件，每一处用 `RH add-change` 记录（格式见 `review-run` 第 8 步；`why` 里写用户的原话或反馈编号），最后 `RH revise-end <会话>`。
   - 要改的发现：用 `anchor` 定位原文；有 `suggested_fix.replacement` 就以它为准，否则按 `suggested_fix.text` 和用户的补充修改。"一类问题"把 `instances` 一起改。
   - 改选的决策点：改陈述这个选择的段落，并顺着改依赖它的下游内容（解释、结论）。数字只能换成已保存的结果文件里已有的；需要新数字时，不自己算，告诉用户要先重跑什么。
   - 用户的回答：按回答修改相关段落。
   - 只改清单里的内容。用户自己改的、关闭的一律不动。
   - **问题出在代码或数据上**：AI 不改代码、不重跑。告诉用户哪里要改、改完要重跑什么；用户重跑之后，再按新的结果文件改报告副本。
5. **再审改动**：按 `review-run` 的"再审"一节审这次改动的部分和它的下游，以及标为 `invalidated` 的决策点。界面开着的话会自动刷新。
6. **写回**（用户签收"交付"，或说"写回"时）：
   - `RH diff <会话>` 给出相对原版（`baseline/`）的全部差异。改动多时先用几句话总结（AI 自改几处、按用户反馈改几处、撤销几处），再给差异。
   - 明确问一句：写回原文件吗？
   - **必须得到用户在本次对话里的明确同意**，然后 `RH writeback <会话> --yes`。原文件在会话开始后被别人改过时脚本会拒绝（退出码 3）：把冲突告诉用户，商量怎么合并，不要强行覆盖。
   - 不同意就停在这里，副本留在会话里。
7. **回顾这次审阅**（最后一步，主动进行）：按 `review-learn` 回顾用户在这次审阅中的回应，提出改进今后同类审阅的建议，请用户逐条确认。

## 规则
- 修改原文件前必须得到用户在本次对话里的明确同意；之前的同意不算。用户说过某个项目只能读、不能改的，永远不写回。
- 不写 `feedback.jsonl`：那是用户的记录。用户在对话里给的反馈，按 `review-run` 的"通过对话给反馈"一节替用户记下。
- 改动后的每个数字都要能指回真值（输出文件、命令和结果），和发现的证据要求相同。
- 改不了的（材料不在、需要用户判断）不要猜：列出来，问用户。
